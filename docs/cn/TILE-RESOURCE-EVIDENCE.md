# 国服静态牌面资源证据

本次调查只读取公开静态 `sqpack` 资源，核对文件存在性、解码图像、文件 SHA256 和路径 CRC32；没有读取游戏进程或隐藏牌局信息。结果为[纯元数据目录](evidence/tile-resource-catalog.json)，不包含本机路径或游戏图像。

固定范围：国服客户端 **2026.09.15.0000.0000**；Lumina **0.0.0-preview.0.384+cb3511aa350b72b5112d740fbe3a522d305fd808**，程序集 SHA256 为 `59A5122E9543B07B0FC3D3D4D461D612A37BF377ED9ECCC6123BEF8D7607D805`。不同客户端或依赖版本需要重新核验。

| 实际存在的图标 ID | 静态视觉核对结果 |
| --- | --- |
| 76001–76037 | 传统样式的 34 种牌及三种赤五，已逐张查看；76032 是白牌空白面，76035–76037 是赤五万/筒/索。 |
| 76041–76077 | 数字、圆形头像和剑/仙人掌样式的 34 种牌及三种赤五，已逐张查看；76072 是白牌空白面，76075–76077 是赤五。 |
| 76081–76117 | 第三套 37 个牌面样式资源已查看，但特殊字形的牌义未独立确认；`CandidateTileKind34`、`CandidateRedFive`、`ChineseName` 均保持 `null`。 |

三个区间各有普通 `.tex`（40×52）及 `_hr1.tex`（80×104），目录共 **111 个 ID、222 个实际存在的路径**。`76000/76040/76080` 为牌图标占位图，`76120` 为敌手头像占位图，`76121–76129` 为 NPC 头像，全部排除。

可按目录的虚拟资源 `Path` 用上述固定 Lumina 从同版本客户端获取 `TexFile`：对原始 `TexFile.Data` 计算 SHA256，并与 `ByteCount`、`Header.Width/Height` 一起核对。`Candidate*` 是静态图像的候选牌义，不是采集到的手牌。目录 `Evidence` 中的图片文件名仅标识当时本地查看的拼图；图像未随本项目分发。

路径散列采用 **CRC-32/ISO-HDLC**：UTF-8 字节，不含末尾 NUL；反射多项式 `EDB88320`，初值和输出异或均为 `FFFFFFFF`。独立实现验证了 `123456789 → CBF43926`，并逐路径确认 `StandardCrc32 == ~Lumina.Misc.Crc32.Get(path)`。不能直接使用此固定 Lumina 的未取反结果。例如 `ui/icon/076000/076001_hr1.tex` 的标准 CRC32 是 `40F72267`，而 Lumina 返回 `BF08DD98`。

目录内部未发现 CRC32 碰撞，但 CRC32 不是抗碰撞身份凭据。未来最多在版本、白名单路径、模板类型、可见性、几何及正面壳检查全部通过后，用实际采到的牌面资源 hash 做受控诊断比对；不能仅凭 hash 命中认定真实手牌、摸牌、排序或牌局完整性。

**0.1.1.2 的第三份实机采集已有442个第二套高清图标与哈希配对吻合、两次人工一致确认。** 0.1.2.0的中文下方牌面解码只支持前两套具备静态牌义证据的目录，必须同时匹配IconId和对应普通/高清路径哈希；第三套仍拒绝，不做仅凭hash的回退。连续两次独立采样一致才显示局部识别；不能把它称为完整手牌、摸牌身份或可决策状态。实时建议和自动操作仍禁用。

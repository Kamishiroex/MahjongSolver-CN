# 0.2.0.1 上游玩法实验移植

本文保留 0.2.0.1 时期的移植记录；当前构建与运行时兼容范围见 [版本证据](VERSION-EVIDENCE.md)。

本文描述该历史版本已实现的手动提醒与自动打牌路径。固定上游提交为 `21ae5ca9aa1fa3785baa540245b51efa346f9d37`；目标仍是国服 `2026.09.15.0000.0000`、Dalamud `15.0.3.5 / API 15`、ClientStructs `f824354f4a6a2b1cd16cc8fcb670c7a66bf64880`。依据见 [版本证据](VERSION-EVIDENCE.md)。

**玩法已经接入；国服整局读取与自动操作尚未实机验证。** 本版允许显式开启上游实验流程。上游偏移、状态码和回调均标为实验假设，不冒充新增国服确证映射。

0.2.0.1 修正一番自摸门槛、杠后牌数检查和可见和牌菜单识别，增加自动本地停止记录；证据与限制见 [本次修复说明](CORE-VALIDATION.md)。

## 模块与改动

0.2.0.3 新增放弃菜单关闭的结果观察，活动模式切换保留持续读取历史，副露推断延后期间暂停策略，缺失历史给出具体错误。详见 [停止原因分析及修复](CORE-VALIDATION.md)。

- [CN入口](../../Mahjong.Plugin.CN/Plugin.cs)保留版本核验、命令、窗口与诊断；[轻量玩法运行时](../../Mahjong.Plugin.CN/Experimental/UpstreamRuntime.cs)在用户选模式后才创建读取器、聚合器和多玛规则的 `EfficiencyPolicy`。未构造上游完整插件、DI、遥测上传、原始内存记录器或输入 Hook。
- [AddonEmjReader](../../Mahjong.Plugin.Dalamud/GameState/AddonEmjReader.cs)加载实际安装目录的 `layouts/emj.json`、`layouts/emj_l.json`，监听与轮询 `Emj/EmjL`。移除了读取必须存在输入事件记录器的前提；没有开启该记录器来迁就读取。
- [StateAggregator](../../Mahjong.Plugin.Dalamud/GameState/StateAggregator.cs)连接当前状态与原引擎，缓存推荐和评分。读取失败、schema不一致及退出时清空缓存；修正候选组合变化时旧建议可能被保留的问题。
- [中文窗口](../../Mahjong.Plugin.CN/MainWindow.cs)提供手动提醒、自动打牌、立即停止，显示推荐、三个备选、向听/进张/宝牌保留等已有评分及原始理由。手动模式不创建自动循环，也不发送输入。
- [AutoPlayLoop](../../Mahjong.Plugin.Dalamud/Actions/AutoPlayLoop.cs)与[InputDispatcher](../../Mahjong.Plugin.Dalamud/Actions/InputDispatcher.cs)复用原上游出牌、吃碰杠、立直、荣和、自摸、放弃和结算下一局流程。新增排队代次取消、执行前权限检查、状态一致性及提交后的变化观察；原来停止后延迟闭包仍可执行的缺口已补上。
- 自动每次加载关闭，配置写盘也不保存开启状态。首次无桌可待命，已入桌后关闭牌桌则停止，需要重新开启。自动模式默认开启结算后的下一局，可在窗口取消。回调提交成功只表示已提交，不能证明客户端执行正确。

严格诊断仍通过独立的 `CnSession`、可见图像和布局探针运行，未伪造其国服完整状态验证标记。实验玩法直接使用上游 `StateSnapshot` 路径。因此历史诊断文档中的“未启用操作”描述其当时版本和严格诊断模块，不代表本版的玩法模式。

## 上游已有的限制

1. **座位、局风与局数不完整。** 旧模型的0值占位保留，但 `SeatInfoKnown=false`，不能据此宣称自己是东家或当前东场。完整局数、本场、供托和立直状态没有因为移植获得可靠来源。
2. **牌河和其他玩家副露缺失。** 两个 profile 未填写牌河数组偏移，弃牌计数不能还原每一枚牌；其他玩家副露、立直、一发等仍有上游空值或默认值。这会影响安全牌、进张和攻守估计。默认 `false` 不代表实机确认不存在。
3. **自家副露主要靠变化推断。** `MeldTracker` 根据手牌减少、弃牌计数与动作记录补全副露；中途启用或重载可能缺历史。退出清理避免上一桌沿用，但不能恢复缺失副露。
4. **暗杠/加杠仍有乐观更新。** 上游在回调提交后记录或升级自己的杠；本版增加后续状态观察，但还没有逐组核对真实副露图像。提交成功与副露已落地之间仍存在假设。
5. **赤五与具体弃牌槽位。** 引擎以34牌种决策，赤五会映射为对应五的牌种并另计赤宝牌数；相同牌种、排序后槽位和独立摸牌身份仍可能受上游寻槽规则影响。严格诊断中识别出了赤五，并不等于玩法路径会保留相同实体。
6. **宝牌与剩余牌估算。** 上游只读取一个宝牌字段，未完整区分国服多玛式直接显示宝牌与传统式指示牌模式。剩余牌用初始牌数减弃牌数估算，不能完整反映鸣牌、杠和补牌。
7. **决策质量独立于适配。** 多玛规则和原策略已经接入，但向听、进张、押退、杠后计数与名次估计都有上游假设。缺公开牌信息时仍可能给出较差建议；不承诺最优弃牌或胜率。

## 导出与隐私边界

0.2.0.1 在停止活动模式时自动保存本地 `diagnostics/gameplay-stops/mjcn-stop-*.json`，包含版本、首个停止原因、原模式、最后公开状态和动作，最多保留 20 份。写入通过有界后台队列；错误不影响停止，不自动上传。卸载后的写入通过后台任务完成，不阻塞框架线程。

“导出当前助手快照”生成本地 `mjcn-gameplay-*.zip`，内含 `gameplay.json`：版本、模式、错误、当前公开结构化状态、建议、评分及最近动作。快照可能含自己的手牌和局面；用户自行决定是否提供。它不包含账号、聊天、玩家姓名、原始内存、内存地址或他家暗手，不自动上传。没有读取结果时不会为了导出捏造状态。

玩法读取使用上游私有内存字段及动作标签解析；上述“公开”描述目标状态模型和导出字段，不代表每个国服偏移已经证明只指向预期字段。未知布局的根本风险仍由本页“实验假设”标识。原始内存 dump 与自动网络上传均未开启。

可选结构诊断保留自己的采集白名单、容量上限、资源校验和停止规则，导出 `capture.zip`；这与玩法快照不同。现有四份记录足以继续离线分析，使用本版不要求先重采。

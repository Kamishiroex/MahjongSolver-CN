# 0.3.0.0 公开牌局只读监视器

0.3.0.1 补充等比例 UI 缩放支持，修正 140% 窗口下所有牌面被拒绝的问题；详见[缩放修复及实录分析](SCALING-CAPTURE.md)。无需改成固定缩放比例。本页的字段范围和模式边界继续适用。

本轮落实[开发计划](CORE-VALIDATION.md)的 P0、P1 和 P2 诊断基础。监视器不调用旧策略、不创建自动操作循环，没有接入 akochan、Mortal 或任何在线服务。已有实验手动/自动模式继续单独选择，不能把该路径的占位值当成新的可信读取结果。

## 使用

1. 更新后 `/mjcn` 确认版本 `0.3.0.1`，沿用七天测试码及精确版本检查。
2. 输入 `/mjcn monitor`，或在“公开牌局（只读）”页点击“开启只读监视”。这会取消旧排队操作、停止实验打牌和已有整场采集；已有采集在后台封存。
3. 入桌后查看下方可见牌面、状态版本、四方字段和缺失原因。每秒两次独立采样；稳定图像可能属于结算画面，不能据此当作完整手牌、摸牌或可出牌状态。
4. “导出公开牌局诊断”显式写入本机 `diagnostics/mjcn-public-*.zip`。窗口显示实际路径；不自动上传，也不需要一直录制整场。
5. `/mjcn stop` 同时停止监视、建议、操作和采集。退桌、卸载、授权到期、版本错误及 60 分钟上限同样停止。重新进入需要主动启用。选择实验手动/自动或整场采集会退出只读监视。

新监视模式不持久化为启动默认项，不改变旧配置格式、用户调参或授权记录。旧配置无需手工编辑。移除插件的步骤沿用 [README-CN](../../README-CN.md)；新诊断包仅在本机，可在不再需要时手工删除。

## 字段质量与支持范围

值是否存在 (`Known / Unknown / Conflict`)、来源 (`Observed / Derived / LegacyAssumption`)、映射是否验证 (`Candidate / Validated`) 分开记录。稳定性单独表示。字段带采样序号、UTC 时间、来源标识、证据及未知原因；未知不序列化成默认零、未立直或空副露。

| 字段 | 本轮实际输出 | 边界 |
|---|---|---|
| 下方可见牌面 `LowerVisibleFaces` | 严格父链、壳、目录/哈希检查及两次独立稳定采样后，输出牌种、赤五、显示顺序、UI 路径与状态版本 | 已有资源映射及有限人工核对支持；不认定手牌完整、主动回合或永久实体身份 |
| 完整自家实体手牌、独立摸牌、合法动作 | Unknown | 不把最右牌当作摸牌，不把下方图像直接送给 AI |
| 四家牌河、副露、声明立直/成立、点数、门风 | Unknown，分别给原因 | 未知副露不是“无副露”，未知立直不是“未立直” |
| 玩家固定编号与当前庄家 | Unknown | 屏幕下/右/上/左与固定 PlayerId、当局门风严格区分 |
| 场风、局数、本场、供托、剩余牌、规则/结束条件 | Unknown | 不用旧模型零值或弃牌计数估算冒充实读 |
| 宝牌显示与显示模式 | Unknown | 直接宝牌与指示牌分开建模，模式不明时不推导 |
| 公开区域候选 | 已有元数据记录数、拒绝数及区域名称 | 节点数不是牌数、clone 编号不是先后顺序；没有扩展 face 或文本读取白名单 |

本轮仅支持固定 `Emj` 下方图像目录及已有布局诊断。`EmjL`、其他牌面主题、完整国服规则组合没有因此获得支持。来源范围及重新检查的原始记录见 [PUBLIC-MONITOR.md](PUBLIC-MONITOR.md)。

`SessionId` 仅标识一次主动开启的观察会话；`StateRevision` 每次观察/失效更新并绑定 UI 槽位。`RoundId`、`DecisionWindowId` 保留未知，不通过帧号猜局数或决策窗口。当前同步始终标记历史缺口；尚未构建 P3 事件历史。停止后的最后观察只用于标为历史的导出，不返回实时界面或策略。

## 后端就绪报告与迁移

`ReadinessProfile` 可以声明后端所需字段、稳定/同步要求及支持规则。本轮提供只读诊断契约和完整决策输入契约，后者不是已安装的 AI。关键字段未知、候选映射、旧假设、冲突、历史缺口、旧版本槽位或规则不符时给出字段路径与原因；只读诊断仍可用。没有就绪时静默回退旧策略的路径。

已有 `VisibleSnapshot` 通过保守适配器保留旧值、赤牌和槽位，并标成候选/旧假设；原按门风排序的座位保存在独立旧字段中，不擅自改成固定玩家或屏幕位置。未设置的新字段默认 Unknown。新字段模型使用不可变托管记录及数组，不携带游戏指针。

## 导出内容

- `manifest.json`：版本、固定 profile/ULD 身份、导出时间、是否实时、当前/最后尝试状态；引擎为 `none`。
- `public-state.json`：最后一次带字段质量的公开观察，停止后明确标为历史；尚未采样时为 null。
- `validation.json`：完整决策输入的缺失、冲突与兼容性检查；无观察时为 null。
- `evidence-summary.json`：当前受控候选接受/拒绝及区域元数据计数，不能当作事件流或牌数。

不含原始内存、进程地址、账号、姓名、聊天、他家暗手或隐藏牌资源。采样仅保留当前和最后一个不可变投影；显式导出最多一个在途任务。原整场记录仍使用原有有界队列、大小上限和白名单。此 ZIP 不具备 P4 的完整事件/决策回放格式，不伪造空事件表示完整。

## 实机验收与下一项最小任务

新监视入口、界面和导出仍待国服实机验收。已有原包已在本机复查，本轮无需重采一整桌。最小验收：NPC 入桌前执行 `/mjcn monitor`，看到牌后静止约一秒，确认下方牌面逐张及顺序、赤牌一致；“完整手牌、摸牌、牌河、副露、立直、点数、门风、宝牌模式”仍明确未知。点一次导出，回传该 **`mjcn-public-*.zip`**；若牌面不同，仅附导出时刻的麻将区域截图。然后退桌，应显示停止，重新入桌不会自动恢复。

下一项开发任务是用已有原始样本与同步人工标签确认独立摸牌槽及排序变化；证据不足的阶段继续候选诊断。完整公开牌河/副露、事件重建、外部引擎和新 AI 自动操作依次保持后续里程碑，不把本轮 UI 或合成测试当作这些能力通过。

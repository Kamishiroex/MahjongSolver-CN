# 0.5.0.0 事件日志、公开牌河与恢复

**开发中，尚未发布。以下为当前源码实现的用法，不代表安装索引已经更新或整场国服实机验收完成。**

## 使用

更新后核对窗口版本，按原方式选择手动或自动。事件日志自动开始，不必开启整场结构诊断。

- 临时停止打牌：`/mjcn pause` 或“立即暂停打牌”。建议、排队操作关闭，读取器继续只读记牌。重新选择模式时复用现有跟踪历史。
- 卸载重载后：在原牌桌使用 `/mjcn recover`，或点“事件日志与恢复”→“重新读取日志并核对桌面”。等待当前运行状态之后新采集的两次稳定公开画面。匹配成功后主动选择手动或自动。
- 反馈问题：`/mjcn logs`，只回传生成的 `mjcn-logs-*.zip`；其中仅有 `events.jsonl`、`errors.jsonl`，不会自动上传。
- 停止全部：`/mjcn stop`，或“停止全部读取与操作”。关闭窗口本身不会关闭已选模式。

## 两个日志文件

本机目录：`%APPDATA%\XIVLauncherCN\pluginConfigs\Mahjong.Plugin.CN\logs\mjcn-game-<时间>-<随机ID>\`。一个目录对应一段观察会话，可能跨多局；边界或不确定边界记录在事件中，不用目录名伪造牌局 ID。

| 文件 | 内容 |
|---|---|
| `events.jsonl` | 版本、公开桌面、原策略状态、候选摸/弃牌、立直/点数/副露库存变化、操作提交、暂停/结束、历史缺口及恢复结果 |
| `errors.jsonl` | 读取拒绝、状态矛盾、操作拒绝、停止错误、恢复错误；附事件位置，不记录无关账号或聊天 |

每行有 schema、会话 ID、递增序号、UTC 时间、类型、载荷、前行摘要和本行 SHA256。摘要用于检测损坏和乱序，不是防篡改签名。后台有序追加；异常退出仅接受已完整写入的行，未完成尾行标为部分记录。完整坏行、摘要错误或版本不符的日志不作为恢复证据。

日志不读对家暗手、暗杠背面的隐藏牌面，不保存旧建议或可执行队列。恢复记录始终 `AutomaticEnabled=false`。原读牌器仍标 `LegacyAssumption/Candidate`，连续两帧一致不会升级为可信 AI 输入。

上限：128 KiB/行、32 MiB/文件，日志目录总计256 MiB、最多256个本插件会话目录，排队128项。超限或写入失败会暂停打牌并提示 `JOURNAL_*`，不静默丢记录。导出并停止后，可将旧目录移出 `logs` 保存；插件不自动删除日志。

## 牌河和事件范围

依据见 [PUBLIC-TABLE-READING.md](PUBLIC-TABLE-READING.md)。新增四方可见牌河，以及受支持模板上正常露出的副露牌面，记录赤五、坐标、朝向、槽位、组及拒绝原因。背面、遮挡、未知资源、异常矩阵及过渡状态拒绝。窗口按屏幕空间展示，不把节点编号或位置冒充发生时序。

仅当相邻原快照有唯一净差分，才给出候选摸/弃牌。未知牌种记未知，跨多个动作保留缺口。副露库存可能来自旧推断或提交后的假设，因此记库存变化，不当作吃碰杠成功。菜单出现或回调提交都不证明荣和/自摸发生；点数变化也不会直接认定为和牌或流局。

**完整 AI 历史尚未完成：** 对手摸牌、严格弃牌时序、被鸣走牌的位置、摸切/手切、固定玩家映射、立直成立、和牌/流局结果及完整副露来源仍有证据缺口。真实 akochan 离线接入保留，未因此开启当前国服实时 AI。事件日志提供后续分析基础，不能称为已完整验证的牌谱。

## 恢复条件

正常暂停保留读取器和副露跟踪，只销毁策略/建议/操作循环。重新选择模式建立新队列，不复用旧建议。

跨重载读取同客户端、框架、结构及语言的最近日志，最多32个候选点；旧诊断包没有这些恢复点。本家手牌须与独立公开图像逐牌种和赤牌一致，四河区域须完整可读，各组本家副露须稳定且全部露出3或4张可解码牌面。固定两背两相同正面的非五暗杠可按公开形状推导四张库存，并且旧记录也必须为同种暗杠；背面仍保持未知，不伪造为看见四张正面。五的暗杠存在隐藏赤五身份歧义，暂不恢复。数量、牌种及赤牌逐组匹配旧库存；来源保留旧实验数据，不升级为完整 AI 状态。

中断后允许有普通摸弃进度：旧记录已有公开河牌锚点，当前四河计数不减少、公开库存包含旧内容、点数及宝牌显示一致、当前手牌库存合法。匹配不证明遗漏顺序。超过6小时、换局/退桌、河牌减少、漏加杠增加第四张、未支持的暗杠形状及未知槽等拒绝套用旧状态。成功仍暂停，由用户选择模式。

读取异常、历史缺失和动作超时会暂停打牌，并尽量保留只读跟踪；离桌、版本失效和卸载清除观察会话。测试码有效期、精确版本和每次输入前检查均保留。

## 本地分析

```powershell
python scripts/analyze-game-logs.py "<日志目录或mjcn-logs ZIP>" --output ".work/game-log-summary.json"
```

仅输出新文件；按原始 UTF8 逐行校验摘要链，汇总版本、事件类型、错误及缺口，不输出完整牌面或无关信息。完整正常记录返回0，损坏返回1，未完成尾行保留有效前缀并返回2。具体限制与测试见脚本和 `tests/test_analyze_game_logs.py`。

新增路径**已实现**，已执行的本机编译与测试记录见[开发验证报告](CORE-VALIDATION.md)；没有发布0.5.0.0附件。**国服整场实机验证待完成**。局部只读实测见 [LIVE-PUBLIC-STATUS-EVIDENCE.md](LIVE-PUBLIC-STATUS-EVIDENCE.md)，它不等于新四河全部场景和跨重载恢复已验收。

离线覆盖固定图像/旋转/等比缩放、背面/遮挡/第4槽、双采样、日志往返/截断/损坏/乱序/重复键、版本/库存/赤牌冲突、漏加杠、暂停/切换/卸载、恢复后输入关闭，以及操作提交不等于发生。

最小实测只需正常使用已有玩法，中途暂停再继续。要验证跨重载，则在同桌暂停、重载、执行 `recover`。反馈一个两日志 ZIP 即可；不要求用户研究内存结构。完整验收应覆盖摸弃/排序/赤五、吃碰后三种杠、立直/荣和/自摸/流局、换局/退出/重新启用和动画过渡；分别评价读取准确性与建议质量。

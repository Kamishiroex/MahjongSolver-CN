## 已定位的拒绝原因

共 1023 次下方候选观察，全部被 `LOWER_ROW_TRANSFORM_UNVERIFIED` 拒绝。其错误元数据一致：Image 节点 4 的局部 `ScaleX/ScaleY=1`、旋转为 0，而缓存变换矩阵的对角项均为 `1.4`，两个非对角项为 0。

旧检查要求整条父链的缓存矩阵均为单位矩阵，因而把这个正均匀缩放也拒绝了。这里只能确认记录中的变换，不能反推用户具体修改了哪个界面设置。

拒绝发生在牌面资源读取前：1023 个候选的图标和路径哈希均为空，稳定牌面帧为 0；没有可用于确认牌种或赤五的新样本。候选数量分布为 0/13/14/15 个分别 7/57/18/2 帧，独立节点 135 的候选出现于 19 帧；这些数量和位置均不能证明摸牌身份。15 个候选的过渡状态仍应拒绝。

本包还包含 3281 条公开区域元数据：下/右/上/左牌河候选分别 621/687/858/807 条，宝牌显示区域 308 条。没有下方副露元数据记录。以上均为重复节点记录次数，不能换称牌数、副露组数或宝牌数。

因此本次可以确认采集封存正常、版本与 ULD 匹配、缩放拒绝原因可定位，并确认失败时未沿用牌面。不能据此宣称 P1 的牌面展示或 P2 的完整公开字段实机验收通过。

## 固定源码与静态模板依据

屏幕投影采用本机固定版本的 [Dalamud `NodeBounds.cs`](https://github.com/ottercorp/Dalamud/blob/cac6159a2c76e62a4e1f7bc347454c205808bb04/Dalamud/Interface/Internal/UiDebug/Utility/NodeBounds.cs)。其 `TransformPoints` 从叶节点沿真实 `ParentNode` 向上，对每层使用局部位置、原点、旋转和缩放。

在本次允许的零旋转范围内，每一坐标轴等价于：

```text
p_next = localPosition + localOrigin + (p - localOrigin) * localScale
```

## 0.3.0.1 实现范围与保护顺序

修正处理的是**可表示的正均匀缩放**，不把 `1.4` 作为特例或新增白名单常量。任意缩放仍须通过有限数值、累计矩阵、屏幕几何及既有资源检查。旋转、镜像、负值、非均匀缩放、非有限值、溢出、退化矩形和不一致缓存继续拒绝。

读取顺序保持为：

1. 精确客户端/框架身份、ULD 哈希和现有可见性检查。
2. 限定下方路径与模板类型；核对完整实际父链、包装节点、归属和终止根，排除循环及超深链。
3. 分别投影 face/shell，核对缓存位置、同一父节点、对应缩放与局部尺寸；在资源读取前检查全部候选数量、重复路径及屏幕矩形重叠。
4. 先确认 shell 当前为既定正面部件及受支持纹理哈希；全部通过后才读取当前 face 部件的图标 ID 与路径哈希。
5. 仅对同一已审核资源目录中双字段匹配的结果解码；仍需两次独立一致观察才能显示稳定下方牌面。完整手牌、摸牌身份和合法动作仍不由此推断。

`HandFaceCandidate.Width/Height` 在 0.3.0.1 改为 `float`，通过投影的候选使用**屏幕单位**，保留非整数缩放结果；不四舍五入回局部尺寸。拒绝候选不属于可使用的投影结果。`UiNode.Width/Height` 仍为**局部尺寸**，其 X/Y 则是原有屏幕缓存位置，分析器不得混用这两种尺寸语义。

启用受控公开布局诊断时，`PublicLayouts` 新增 `lower-row-geometry`，记录该白名单 face/shell 已核对父链的数值元数据及拒绝类别。它不增加其他牌区，不导出像素、文字、资源路径、内存地址、账号或聊天。该区域的条数仍然是元数据条数，不是实体牌数；监视器平时不会自动把记录写盘。
